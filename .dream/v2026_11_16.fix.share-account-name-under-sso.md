# 🌙 dream: share the account-name lookup under sso profiles

- kind = fix
- owner = sdk-environment
- caught 2026-11-16

## .the cue that fired
the 1.vision assumption review of v2026_11_16.fix-get-environment-cold-start-throttle found the cache key (hash of the resolved access key id) differs per process under sso.

## .the gap, precisely
`@aws-sdk/credential-provider-sso` calls `GetRoleCredentials` per process and keeps no disk cache of role creds. each process holds a fresh temporary access key id → its own cache key → its own `GetAccountInformation` call. the throttle retry guards it, but the burst stays.

## .the shape of the fix
key the shared cache by the sts caller arn (`GetCallerIdentity`): stable across processes under sso, and safe (it names the exact principal). adds `@aws-sdk/client-sts` as an optional peer dep, plus one sts call per process (sts allows a far higher rate than the account api). fall back to the access key id key when sts is absent.

## .why it is not done in this round
the measured failure (issue #17) runs on env creds, which the access-key key already shares. the sts path adds a dependency; the wish asks for the smallest change.
