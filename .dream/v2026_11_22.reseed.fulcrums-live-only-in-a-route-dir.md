## .the cue that fired
sdk-environment#18 review: the commander found a `.fulcrums/` dir at the repo root, outside the route dir, and ruled it should be forbidden, with the fix dispatched upstream so the behaver knows where fulcrums are allowed.

## .the gap, precisely
- the driver rule names the home as `$route/.fulcrums/`, but no behaver brief says it, and no hook refuses a write elsewhere
- a route on a behavior (`.behavior/v$date.$slug/`) left its fulcrum inventory at `./.fulcrums/`, so it shipped in the pr beside, not inside, the route it records
- a root `.fulcrums/` collides across routes: two routes on one repo would write one inventory

## .the shape of the fix
- behaver: a brief `rule.forbid.fulcrums-outside-the-route-dir` — fulcrums live at `$route/.fulcrums/` only; cite it from the behavior templates that mention fulcrums
- driver: a PreToolUse hook that refuses a write to any `**/.fulcrums/**` path not under the bound route dir, and names the fix (`$route/.fulcrums/<file>`)
- clamp: a write to `./.fulcrums/x.md` with a bound route → refused, exit 2; a write to `$route/.fulcrums/x.md` → allowed
