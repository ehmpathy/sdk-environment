# 🌙 dream: teesafe writes its input byte-for-byte, final newline included

- kind = reseed
- owner = ehmpathy/rhachet-roles-ehmpathy (mechanic role, `skills/claude.tools/teesafe.sh`)

## .the cue that fired
sdk-environment#18 tree cleanup: 16 deleted review files had to go back to HEAD. only read-only git verbs are paved, so the restore was `git show HEAD:<path> | rhx teesafe --into <path>`. git read every restored file as modified: the diff was `\ No newline at end of file`.

## .the gap, precisely
- teesafe drops the final newline of its input (the shell `$(cat)` capture shape)
- so `cmd | teesafe <file>` cannot reproduce a file, and a restore from git is never clean
- it also echoes the whole input to stdout, which makes it unfit for a large or binary blob (`bin/*.bc`, 100 MB)
- and no paved verb restores a tracked path to HEAD (`git restore` is unpaved; `git.crew.reset` lives in a role this repo does not link)

## .the shape of the fix
- stream stdin straight to the file (`cat > "$file"` or `tee`), so bytes, newlines, and binary pass through untouched
- add `--quiet` (or make it the default for `--into`) so a large write does not flood stdout
- clamp: pipe a file that ends in `\n` and one that ends in `\n\n` through teesafe; assert `cmp` equal; revert the fix, see it red
