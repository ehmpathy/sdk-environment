# 🌙 dream: sedreplace answers --help, and a `**` glob says when it skipped dot dirs

- kind = reseed
- owner = ehmpathy/rhachet-roles-ehmpathy (mechanic role, `skills/claude.tools/sedreplace.sh`)

## .the cue that fired
sdk-environment#18 fulcrum id pad: `rhx sedreplace --help` exited 2 with `unknown argument: --help`; then a `--glob '$route/**/*.md'` swap reported `no files contain pattern` for links that sat in `$route/.reviews/`, a dot dir the glob silently skipped.

## .the gap, precisely
- no `--help` / `-h`, against `rule.require.help-on-demand`; the usage line omits `--include-ignored` and the `@stdin` form
- `**` skips dot dirs with no note, so an empty result reads as "none exist"
- patterns are literal, but naught says so: a caller tries a regex and reads its silence as no match

## .the shape of the fix
- `--help` prints usage, every flag, literal-pattern note, and the `@stdin` examples from the header
- when a glob skipped dot dirs that hold a match, say so and name the explicit glob, as `grepsafe` already does ("23 hidden file(s) hold a match")
- clamp: a match only under `x/.hidden/a.md` with `--glob 'x/**/*.md'` → the result names the skipped dot dir

## .why it is not done in this round
another repo's skill. this round named the dot dir in an explicit glob.
