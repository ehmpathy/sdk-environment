# 🌙 dream: share the account-alias lookup across processes too

- kind = fix
- owner = sdk-environment
- caught 2026-11-16

## .the cue that fired
the 1.vision review of v2026_11_16.fix-get-environment-cold-start-throttle asked whether the scope was misdirected. `getEnvironment` runs `fromAwsAccountAlias` (iam `ListAccountAliases`) before `fromAwsAccountName`, once per cold process.

## .the gap, precisely
`getEnvAccessFromAwsAccountAlias.ts` calls iam once per cold module registry, the same burst shape issue #17 measured for the account api. no throttle was measured there yet.

## .the shape of the fix
wrap the alias fetch in the same cross-process cache + throttle retry pair, keyed by the same caller key. iam's throttle error code differs from the account api's (http 400, not 429), so the throttle check needs that code too. swap the alias parser's inline credential allowlist for `isCredentialError`: today the inline copy reads a TypeError that names credentials as a skip, which hides a code defect; the swap changes that behavior, so it needs its own clamp. lift the shared cache setup (ttl, retry, dir, key read) to a common home only then, per most-common-denominator.

## .why it is not done in this round
the wish asks for the smallest change that meets done; done names the account api only. no measurement shows iam throttles.
