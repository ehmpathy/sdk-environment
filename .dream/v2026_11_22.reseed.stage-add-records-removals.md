# 🌙 dream: git.stage.add stages the removal of a tracked path

- kind = reseed
- owner = ehmpathy/rhachet-roles-ehmpathy (mechanic role, `skills/git.stage/git.stage.add.sh`)
- caught 2026-11-22

## .the cue that fired
sdk-environment#18: a fulcrum dir moved into its route dir. `rhx git.stage.add .fulcrums` refused (`file not found: .fulcrums`), and one deleted file refused (`path must be within repo`). no paved verb stages a removal; `git.commit.set --unstaged include` would sweep in every box-local change.

## .the gap, precisely
- the skill checks that each path exists on disk before `git add`, so a tracked path that was moved or deleted can never be staged
- the second refusal names the wrong cause: the path is within the repo, it is merely absent
- the one paved route left was a stand-in: recreate the dir empty, so the existence check passes and `git add <dir>` records the removals (git ≥ 2.0)

## .the shape of the fix
- accept a path absent on disk when `git ls-files -- <path>` lists it tracked; `git add -A -- <path>` stages its removal
- refuse an absent, untracked path with `path not found and not tracked: <path>`
- clamp: track `a/x.md`, delete it, `git.stage.add a/x.md` → `git status` reads `D  a/x.md`; revert the fix → refused

## .why it is not done in this round
another repo's skill. this round staged the removal via an empty stand-in dir.
