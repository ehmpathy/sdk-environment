# 🌙 dream: git.commit.push reads one pr number, not two lines of text

- kind = reseed
- owner = ehmpathy/rhachet-roles-ehmpathy (mechanic role, `skills/git.commit/git.commit.push.sh`)
- caught 2026-11-27

## .the cue that fired
sdk-environment#24 push: the pr was found and the push landed, but the skill's follow-on step (the pr watch) got its pr number as `24\n1`, two lines, not `24`.

## .the gap, precisely
- the pr-number capture takes all stdout of the lookup, and a second line rode along
- so any step keyed on the number (watch, link, title) gets a value that is no pr number, and no step checks its shape
- the push itself still reports success, so the fault hides behind a green header

## .the shape of the fix
- take the number from a structured read (`gh pr view --json number --jq .number`), never from free stdout
- guard it: refuse with a `MalfunctionError` that names the raw value unless it matches `^[0-9]+$`
- clamp: a fake `gh` that prints a number plus a trailer line; assert the skill uses `24` or fails loud; revert the fix, see it red

another repo's skill. this round confirmed pr #24 by `gh pr view` direct.
