# 🌙 dream: `git.release --watch` must wait on queued runs of the head

kind: reseed · owner: ehmpathy/rhachet-roles-ehmpathy (mechanic role, `git.release`) · caught 2026-11-27

## .the cue that fired

after a push to pr #24, `rhx git.release --watch` printed `👌 all checks passed` and `🫧 no runs inflight` in 0s. `gh run list` on the same head showed `test` queued and `provision` in progress.

## .the gap, precisely

the watch reads the check rollup before the new head's runs register, or skips runs whose status is `queued`. it reports a green that belongs to no run yet.

## .the shape of the fix

key the watch on the pr's current head sha. treat `queued` and `in_progress` runs of that sha as inflight. when the head has no run yet, wait a bounded window for one to appear, rather than read an empty set as done. clamp it with a push-then-watch test.

## .why it is not done in this round

the skill lives in another repo; this pr pins the publish npm.
