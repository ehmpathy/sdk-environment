## .the cue that fired
sdk-environment pr #18: `suite / test-commits` red on commit `914a295`, from commitlint `✖ body's lines must not be longer than 100 characters [body-max-line-length]`. the fix is a reword of one body line plus a push with lease. no paved skill does either, so the pr cannot go green without raw `git commit-tree` and `git push --force-with-lease`, which the permission hook blocks.

## .the gap, precisely
- `git.commit.set` makes new commits only; no amend or reword
- `git.commit.push` pushes fast-forward only; a rewritten branch cannot land
- `git.branch.rebase begin` rebases onto origin/main with no message edit
- `git.branch.cutover begin` cherry-picks messages verbatim, onto a new branch (a new pr)
- ⇒ a commit message that fails the repo's own commitlint, once pushed, has no paved repair

## .the shape of the fix
`rhx git.commit.reword --which <sha> -m @stdin [--mode plan|apply] [--push]`:
- guards: the branch is not main/master; every commit from `<sha>` to HEAD is authored by seaturtle[bot]; the work tree is untouched (rewrite via `git commit-tree`, so unstaged edits stay put)
- keeps the tree, parent, author, and the sponsor `Co-authored-by` trailer; forbids an adhoc trailer, as `git.commit.set` does
- replays every later commit onto the reworded one, messages and trees unchanged
- lints the new message with the repo's commitlint before it writes aught
- `--push` = `git push --force-with-lease=<branch>:<old-head>`, gated by the same `git.commit.uses` push grant; never decrements uses
- plan by default: shows old vs new message and old vs new shas

## .why it is not done in this round
another repo's skill, and a force-push verb is a contract a human should rule on. sdk-environment#18 waits on it, or on a human-run reword, for its last red check.
