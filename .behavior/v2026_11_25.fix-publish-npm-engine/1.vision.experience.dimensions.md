# 1.vision.experience.dimensions

the experience: a maintainer's release tag runs `.publish-npm.yml`; a consumer then pins what it published.

## axes

| axis | positions | why it varies on its own |
|---|---|---|
| actor | maintainer · publish job · consumer | each meets a different boundary: merge, runner, registry read |
| upgrade gate | runs (runner npm `< 11.5.1`) · skipped (runner npm `>= 11.5.1`) | set by the runner image's npm alone; independent of npm's registry and of what npm holds |
| installed major | `11` · `>= 12` | set by the version spec in the step; the pin fixes it to `11` |
| engine verdict | accepts runner node · rejects runner node | set by the installed npm's `engines.node` against `.nvmrc`; independent of the major — an 11.x could reject, a 12.x could accept a newer node |
| suite gate (`needs: [test]`) | green · red | set by the test suite on the tag commit; independent of npm |
| version on npm | absent · present, same payload · present, different payload | set by prior publishes; independent of this run |
| run attempt | first · re-run | set by the maintainer; a re-run reads the workflow pinned at the tag, so it repeats the tag's own step, never main's |
| check site | tag (the publish job) · pr ci (the clamp) · dev host (the clamp, by hand) | set by who runs the step; only the tag publishes, but all three meet the same engine verdict |
| `.nvmrc` form | exact (`v22.21.0`) · no `v` (`22.21.0`) · loose (`22`, `22.21`, `22.x`) · alias (`lts/*`) | set by the maintainer; setup-node reads all four, the clamp matches the first three against the current node and sends an alias to fnm |
| spec source | the workflow's literal line · an expression (`${{ … }}`) · the `--spec` flag | set by the caller; only a literal line or the flag names an npm the clamp can install |

## the latent dimension, surfaced

`installed major` and `engine verdict` exist **only where `upgrade gate = runs`**. they are sub-axes of that one position, not peers of the gate: where the gate is `skipped`, no npm is installed, so neither has a value. the catalog walks them nested under `runs`, never as a full product with `skipped`.

`check site`, `.nvmrc` form, and `spec source` hold values only at the clamp (`pr ci`, `dev host`); the tag always reads the literal line on the node setup-node picks. the `upgrade gate = skipped` position applies at every site: a `.nvmrc` node whose own npm is `>= 11.5.1` skips the step at the tag, and the clamp mirrors that skip when it reads the workflow.
