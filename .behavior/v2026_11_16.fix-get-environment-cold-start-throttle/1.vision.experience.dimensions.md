# 1.vision.experience.dimensions

actor: a process that calls `getEnvironment()` (a jest worker, a cli, a lambda).

## the factorization
the behavior has four independent mechanisms. each owns its own axes, so the space walks as four slices, not one full cross-product:

- **share** — decides how many processes fetch from aws. axes: arrival × cache × key
- **fetch** — decides what one fetch yields. it runs the same in whichever process fetches, so it is orthogonal to share. axes: aws reply × temp dir
- **lock fate** — decides whether a waiter can move on. axes: holder fate × arrival
- **trust** — decides whether what sits on disk may be believed. axis: disk state

share fixes WHO fetches; fetch fixes WHAT that one fetch yields; lock fate fixes WHEN a waiter may take over; trust fixes WHETHER a file on disk is the caller's own. cross-slice edges:
- the share and lock-fate slices presume a writable temp dir. when it is unwritable, the shared cache is skipped, every call fetches, and the fetch slice's unwritable cells cover the outcome
- the share and lock-fate slices presume a trusted dir and file (t01, t02). an untrusted one (t03–t06) is read as absent, so the reader fetches as at `cache=cold`
- `key=none` never reads or writes the cache, so the cache axis collapses for it: 3 cells, by arrival

## axes

| slice | axis | positions | why orthogonal |
|---|---|---|---|
| share | arrival | solo · concurrent (N at once) · subsequent (after a prior caller ended) | when a process arrives, independent of what is on disk or which creds it holds |
| share | cache (the last file written, under its writer's key) | cold (no file) · fresh · stale | what is on disk; set by prior callers and the clock, not by this reader's arrival or creds. whether the reader may use it is the key axis's job |
| share | key | same as the cache writer's · other (other creds, or sso's fresh key per process) · none (the client holds no credential provider, as a module-level mock of the sdk builds) | which creds the process holds; set by the env, not by disk or arrival time |
| fetch | aws reply | none (no fetch) · ok · throttled-then-ok · throttled past retries · credential error · other error (5xx, network) · a fault that names credentials but is none (a code defect such as `TypeError: … 'credentials' of undefined`, or a reset socket) | what the fetch yields; independent of the local disk. the last position is a local fault whose text a loose match would read as a refusal |
| fetch | temp dir | writable · unwritable (any node fs fault: EROFS, EACCES, ENOSPC, ENOTDIR, EISDIR, …; or a dir not ours), at any fault site: the dir itself, the file path (a dir sits there: EISDIR), or an ancestor (a file sits there: ENOTDIR) | local fs perms; independent of aws. every site degrades the same way, so the site names where the fault lands, not a new outcome |
| lock fate | holder | lives · dies mid-fetch (pid readable) · throws (lock released in `finally`) · pid unreadable (torn write) · outlives the stale bound (a waiter breaks the lock and takes it anew mid-fetch) · lives and never releases (its lock never reads stale) · dies, and the fs refuses to delete its lock | how the holder's turn ends, and what it leaves on disk; independent of arrival |
| lock fate | arrival | solo · concurrent · subsequent | same axis as above, crossed with holder fate |
| trust | disk state | ours and closed · ours and open to other os accounts · a file another os account owns · a dir that is a symlink · ours, content truncated (torn json) · ours, content of another shape (valid json, no string `value`) | who owns the dir and file, and whether its bytes parse to the shape we write; set by the host, other accounts, and torn writes; independent of arrival, creds, and the aws reply |

the latent axis `arrival=subsequent` was surfaced from a forbidden-cell note that depended on "a later caller". it is now a position, walked in both slices that need it.

every verdict (forbidden and impossible cells too) lives in `1.vision.experience.case=_.md`.
