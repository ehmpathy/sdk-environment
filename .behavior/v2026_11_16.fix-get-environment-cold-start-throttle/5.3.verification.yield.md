### the identity-dependent and dead conditional asserts — fixed
`getEnvAccessFromAwsAccountName.integration.test.ts`, 4 forced-map cases. each asserted only `if (result !== null)`, then pinned `null` by snapshot. ci's identity reads no name (run 27254151595 passed with `null`); this host's identity reads one, so the 4 failed here. the test passed or failed on who ran it, and asserted naught under ci.

- fix, the tier variants: `[case2] an account whose name is known: acme-prod` injects a fake account api with a fixed name, so each variant (default map, exact match, forced test/prep/prod, no-match null) is the same on every runner. each asserts `toBe` and snaps. the tier map is now exercised on ci too
- fix, the real-aws wildcard case: probe once, direct through the sdk, whether this identity may read its account name; assert `toBe(isReadable ? 'prod' : null)`. no branch is left unasserted. it snaps behind `asTierIfNameReadable`, a jest asymmetric matcher that prints one constant, so the snap holds on every identity
- the real-aws forced variants stay under their original names and keys, asserted and masked as the wildcard is; `[case2]` adds the known-name variants beside them, never in their place
- every real-aws case calls the parser with no context, as main does, so the default cache dir stays under test; the readability probe runs per `when` that reads real aws, so the invalid-creds case needs no creds
- the readability probe fails loud off ci (`ConstraintError`, with the keyrack unlock command) when no aws creds load. ci holds no aws creds (its oidc auth step reads `skipped` on run 27254151595), so there each real-aws case asserts the null a caller with no creds gets
- the caught dream `fix.mask-identity-dependent-account-name-snapshot` is fulfilled and removed
- the default-map name case asserts `toBeNull()` beside its `null` snapshot, in place of a dead `if (result !== null)` branch
- the alias test is out of scope (F10) and is back to its main state, unchanged by this fix
