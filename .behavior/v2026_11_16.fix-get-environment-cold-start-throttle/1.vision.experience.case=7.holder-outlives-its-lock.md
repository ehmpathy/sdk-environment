# case=7 — the holder outlives its lock, or never lets go

cells: l14 · l17.

## narrative
worker 3 holds the lock, and its fetch stalls past the stale bound. worker 9 judges the lock abandoned, breaks it, and takes it anew (l14). then worker 3's fetch returns. if worker 3 deleted the lock on its way out, it would delete worker 9's lock, and a third worker would take it too: two fetches at once, the burst this fix exists to stop. so worker 3 deletes the lock only if it still holds worker 3's own pid. it does not, so worker 3 leaves it in place and returns its value.

worker 5 holds the lock and lives, but never releases it: a hung fetch, or a lock whose mtime sits in the future so it never reads stale (l17). worker 12 waits. if the wait had no end, a core `getEnvironment()` caller would hang forever. the wait has a deadline at the stale bound: worker 12 stops there and asks aws direct. the worst case costs one bound's wait, then one call.

## bdd [tn]
```
given a holder whose lock is broken and taken anew by another process while it fetches
  [t0] when the holder's fetch returns
    then the holder returns its value
    then the other process's lock is left in place

given a live holder that never releases its lock
  [t0] when a process reads the account name
    then it waits no longer than the deadline
    then it asks aws direct, once
```
