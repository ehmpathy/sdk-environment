# case=4 — a credential error still returns null; a fault that only names credentials surfaces

cells: f09 · f13.

## narrative
a dev runs tests with no aws credentials, or with bad ones. either the credential read fails (no creds) or aws rejects the call (bad creds). a failed fetch is never cached. the parser returns null, as today, and `getEnvironment` falls through to `fromNodeEnv`. no cache file is written, so a later run with real credentials never reads a stale null.

the null is a quiet fallback, so it must be earned. a code defect can throw `TypeError: Cannot read property 'credentials' of undefined`, and a reset socket can carry text near a credential read. neither is a refusal. if the parser read them as absent creds, the caller would run on with a fallback tier and the real fault would hide. so the parser returns null only for a true credential error; a `TypeError` or a reset socket surfaces loud (f13).

## bdd [tn]
```
given no valid aws credentials
  [t0] when getEnvAccessFromAwsAccountName is called
    then it returns null without error
    then no cache file is written

given a fetch that throws a fault which names credentials but is no refusal (a TypeError, a reset socket)
  [t1] when getEnvAccessFromAwsAccountName is called
    then the fault surfaces to the caller
    then it is never read as absent credentials, so no fallback tier is returned
```

tests: f09 — `getEnvAccessFromAwsAccountName.integration.test.ts` 'invalid credentials provided', `isCredentialError.test.ts` (absent, expired, invalid token, other realm). f13 — `isCredentialError.test.ts` 'a connection reset is not a credential error', 'a code defect … is not a credential error'; the parser returns null only when `isCredentialError` holds, and rethrows all else.
