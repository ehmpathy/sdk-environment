## what
`getEnvironment()` asks aws for the account name once per host per 15 min, not once per cold process.

- the first cold process takes a lock dir (holds its pid), calls `GetAccountInformation`, and writes the name to `tmpdir()/sdk-environment.uid=<uid>/aws-account-name/<sha256(access key id)>.json` (file 0600, dir 0700)
- every other process waits on the lock, then reads the file
- a `TooManyRequestsException` (or http 429) backs off with full jitter and retries, up to 6 attempts over the sdk's own 3
- a dead holder's lock breaks at once; a 60s stale bound backs it up
- any fs fault, or a dir another os account owns, skips the disk cache and asks aws direct; a torn or wrong-shape cache file reads as cold

## contract changes a caller may notice
- `getEnvironment({ cache: 'skip' })` skips the in-process cache only; the disk cache still answers within its ttl. to force a fresh aws read, delete the dir above
- a test that stubs `AccountClient.send` must hold fake env credentials (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`); a module-level mock of `@aws-sdk/client-account` builds a client with no credential provider, so it answers direct, as before
- under a throttle that never clears, the caller sees `TooManyRequestsException` after a bounded wait (~30s), not an endless retry
- profiles that mint a fresh key per process (sso, assume-role) share no cache; the retry is their only guard
