# case=6 — an untrusted cache file or dir is never believed

cells: t03 · t04 · t05 · t06.

## narrative
a shared ci host runs two os accounts. the other account, by mistake or by intent, writes `acme-prod` into this account's cache path under the right hash. if the parser read it, a test suite would map its account to `prod` and aim a test-tier action at prod.

the reader checks the file's owner before it reads (t03). the file belongs to another uid, so it reads as absent: the reader asks aws, and gets its own `acme-test`. the planted file is never believed.

if the cache dir itself is a symlink (t04), it could point into a dir another account controls. the reader refuses the dir: every call asks aws direct, and no file is written through the link. the cost is one aws call per process, as before this fix; the gain is that no other account can steer the answer.

a file we own can still lie. a process killed mid-write leaves torn json (t05); a stray tool, or an older format, leaves valid json with no string `value` (t06). the reader parses and checks the shape before it believes a byte: either file reads as cold, so the reader asks aws once and writes a whole file over it. the next read gets the rewritten value. a torn file never crashes `getEnvironment()`, and a wrong-shape file never hands it a garbage name.

## bdd [tn]
```
given a fresh cache file, under the right key, that another os account owns
  [t0] when a process reads the account name
    then it ignores the planted file and asks aws once
    then it returns its own account's tier

given a cache dir that is a symlink
  [t0] when a process reads the account name twice
    then each read asks aws direct
    then no file is written through the link

given a cache file we own, under the right key, whose json is torn
  [t0] when a process reads the account name twice
    then the first read asks aws once
    then the second read gets the rewritten file, with no second call

given a cache file we own, under the right key, of valid json with no string value
  [t1] when a process reads the account name
    then it reads as cold, asks aws once, and returns its own tier
```

tests: `withCacheAcrossProcesses.integration.test.ts` [case8] (t03), [case16] (t04), [case7][t0] (t05), [case7][t1] (t06).
